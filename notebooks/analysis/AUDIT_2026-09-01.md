### A1 -- V_xc (and DM) loss normalized by the PADDED AO count

Defect. losses.py `_vxc_term` divided the Frobenius error by
`n_ao = vxc_ref_arr.shape[-1]` on both the RKS branch and the UKS branch
(`2 * n_ao * n_ao`), and `_dm_term` divided by
`math.prod(dm_ref_arr.shape)` -- all three read the reference matrix AFTER
shape padding, so padding a molecule from n_ao to n_ao_t silently rescaled
its loss by (n_ao/n_ao_t)^2, up to (54/117)^2 = 4.7x species-dependent
down-weighting on the production basis, while padding.py's module docstring
advertises the pass as "results-neutral". The `_dm_term` site was found by
the pre-edit caller sweep (`grep -n "n_ao" losses.py`), one site beyond the
two the plan named.

Change. `padding._pad_mol_data` records the physical AO count before any
padding as `mol_data["n_ao_unpadded"]`, a traced 0-d array (a Python int
leaf would re-key the JIT cache per molecule and defeat padding's purpose);
`_vxc_term` and `_dm_term` divide by it when present, with the shape
fallback unchanged for unpadded batches.

Evidence (test_vxc_padding_neutrality.py, quadrature-stub V_xc so the
numerator is padding-neutral by construction and any difference isolates
the denominator):
- RED (pytest_a1_red.log): `padding rescaled loss_vxc:
  0.0027495747254749903 vs 0.01718484203421869 (ratio 0.160000 ...)` --
  exactly (2/5)^2 at n_ao 2 -> 5; UKS branch identical; `KeyError:
  'n_ao_unpadded'`; DM twin (pytest_a1_red_dm.log): `ratio 0.160000`.
- GREEN: `4 passed` (pytest_a1_green.log).
- Module suites, each in its own process: test_losses.py `103 passed,
  3 xfailed`; test_losses_step7.py `31 passed`; test_shape_padding.py run
  separately (see the pre-existing batch-abort note below);
  test_training_points.py unaffected.

Batch-run abort, pre-existing. Running
`pytest test_losses.py test_losses_step7.py test_shape_padding.py` in ONE
process dies with SIGABRT (exit 134, `Fatal Python error: Aborted` inside
`jax.clear_caches()` -> `weakref.py:376 remove`) during
test_shape_padding's compile-count test -- WITH and WITHOUT the A1 change
(pytest_a1_suite.log vs pytest_a1_baseline.log, identical failure point).
Standalone, the same test PASSES with the change (pytest_shape_alone.log).
Tracked as item F1: the cross-module `clear_caches` abort makes combined

### A2 -- empty group-scoped anchor allowlist collapsed to regularize-everything

Defect. train.py `_build_group_loss_and_batch`:
`lk["regularize_atom_syms"] = scoped_reg or None` -- when a per-molecule
group contains no allowlisted atom, the intentionally empty scope `()`
collapsed to `None`, which losses.py:1350-1352 documents as "When None,
regularize every single-atom MoleculeSpec (kept for back-compat)". Every
group whose atoms miss the H/Li allowlist silently anchored every atom it
contained (measured on v6 G1: anchor terms leak into 80/270 groups).

Change. Only an UNCONFIGURED run (allowlist absent, None) keeps the
regularize-everything default; a configured allowlist scopes to the group
and an empty scope stays `()`.

Evidence (test_train.py):
- RED structural: `empty group scope must stay empty, got None`.
- RED observable: an H2<->2H group under allowlist ('O',) carries
  `loss_AE = 1.8895680198272532e-05` (the anchor leak on H) where the
  contract requires exactly 0.0. First run of this test died earlier on a
  fixture omission of the ERI tensor (`required_keys=("eri",)`, the same
  keys the sibling test_defused_grad fixtures pass); fixed in the test,
  re-run, and the observable RED above is the true defect signature.
- GREEN: `2 passed` (pytest_a2_green.log); `grep -c scoped_reg train.py`
  = 0 (name fully retired).

### A3 -- barrier heights become trainable (reactants -> TS)

Defect. The three DFS_BH76_REACTIONS entries carried `"ts_species": None`
with comments claiming the TS geometries "are NOT yet staged in this repo"
-- while n2ohts / RKT11 / hf2ts have been staged in the tracked
data/bh76_full_pool.json since 2026-05-29 with geometry, spin (1/2/1) and
charge. bh76_mode="barrier_height" raised NotImplementedError, so no
generation of any campaign could train a transition state.

Change.
- dfs_pool.py: ts_species names the staged TS; barrier_ref repointed from
  the Minnesota REF1 values (82.27 / 7.90 / 105.80) to the GMTKN55
  BH76/.res forward barriers (82.6 / 8.9 / 104.8 kcal/mol -- read from
  scripts/script_data/gmtkn55/BH76/.res in this session and mirrored in
  the tracked bh76_full_pool.json rows bh76_oh_n2_to_n2ohts /
  bh76_oh_ch3_to_RKT11 / bh76_hf_f_to_hf2ts), the SAME reference layer
  the held-out BH76 evaluation scores against; Minnesota values retained
  as provenance comments; stale "not staged" comments corrected.
- training_points.py: `_ts_atoms` resolves a TS from the tracked JSON via
  the existing `load_full_held_out_pools` + `_molspec_to_atoms` path (one
  TS identity shared between training and evaluation); in barrier mode
  `_bh76_point_from_dict` builds species = reactants + TS with coeffs
  (-1, ..., +1) and e_rxn_ref = barrier_ref, so sum(coeffs*E) =
  E(TS) - E(reactants) is a true forward barrier; a dict without a staged
  TS refuses with ValueError naming the reaction.
- Wrong-pin tests deleted/replaced: the `ts_species is None` pin and the
  NotImplementedError gate test; the Vr-Vf consistency test re-anchored
  from cross-set arithmetic (GMTKN55 barrier vs Minnesota Vf) to
  GMTKN55-internal (fwd - rev vs BH76RC, both from the tracked JSON),

  64.91; 8.9-14.4=-5.5 vs -5.44; 104.8-1.5=103.3 vs 103.28); a stale
  82.27 pin in test_training_point_metadata_preserved updated to 82.6.

Evidence:

- GREEN: test_training_points.py `20 passed` (pytest_a3_green2.log).
